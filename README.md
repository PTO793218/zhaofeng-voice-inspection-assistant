# 兆丰语音操作助手及智能检测录入

面向制造业生产现场的语音交互产品原型，围绕生产任务串联查询、进度查看、生产报工与检验数据录入，让操作人员能够用自然语言表达意图，在明确的任务上下文中核对并完成操作。

## 业务背景

生产报工与检验录入都需要准确关联任务、工序和数据字段。同一母任务可能包含多道工序，一次检测又涉及多个检验项目和测量列。简化输入的同时，仍需让操作人员清楚地知道当前处理的对象、即将记录的内容，以及哪些动作需要本人确认。

项目以语音为主要交互入口，保留文字输入和手动操作作为补充，将任务查找、候选澄清、数据校验与人工确认组织为连续的业务流程。

## 我的工作

- **场景梳理**：整理任务查询、进度查看、生产报工和检测录入的操作链路，明确任务、工序与检验记录之间的关系。
- **产品与交互设计**：设计自然语言指令、候选澄清、任务上下文复用和操作反馈，处理数量异常、草稿保护及任务切换等情况。
- **原型落地与迭代**：借助 AI 辅助编码完成可运行原型，通过典型任务和异常场景核对交互流程，逐步完善状态衔接与确认机制。

## 核心体验

### 从任务线索定位到具体工序

用户可以输入任务号、产品或工序等线索。多个工序同时匹配时，助手展示候选并引导补充信息，帮助用户确认具体操作对象。

![根据任务线索展示工序候选与补充提示](docs/screenshots/task-query.png)

### 沿用任务上下文，完成报工复核

选定任务后，输入“完工18，报废0”即可形成结构化草稿，并预览确认后的累计完成数。数量通过校验后，用户仍需核对任务与数量，再进行最终确认。

![生产报工草稿、数量校验与人工确认入口](docs/screenshots/report-review.png)

### 将检测指令定位到目标单元格

“外径 D1，第 2 列，87.39”对应明确的检验项目、测量列和数值。界面同时呈现技术要求、上下限和历史记录，新增测量值经人工确认后保存，历史值保持只读。

![检验项目矩阵与目标测量值确认](docs/screenshots/inspection-confirmation.png)

## 关键设计取舍

| 业务问题 | 设计方式 |
|---|---|
| 同一任务线索可能匹配多道工序 | 展示实际候选，支持补充条件与手动选择，唯一匹配时直接进入任务 |
| 查询、报工和检测之间需要保持对象一致 | 复用当前任务上下文，根据任务状态和关联检验记录判断可用操作 |
| 口述数量或测量值可能存在理解偏差 | 先生成可核对的草稿或目标单元格，校验通过后仍保留人工确认 |
| 任务切换与识别失败可能打断操作 | 对未确认内容提供草稿保护，保留文字输入、错误反馈及会话恢复能力 |

## 当前成果

已形成“查找任务—确认工序—选择操作—核对数据—人工确认”的完整交互原型，覆盖生产报工与智能检测录入两条业务流程，并支持候选澄清、组合指令、数量校验和草稿保护。

原型使用内置任务与检验样例，确认结果保存在浏览器本地会话中，尚未接入正式 MES。语音识别与播报使用浏览器 Web Speech API。

## 技术与运行

前端采用 React、TypeScript 与 Vite，业务和交互测试使用 Vitest、Testing Library。
